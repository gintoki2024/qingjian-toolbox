# 开发与打包

## 运行

仓库根目录可直接运行 `启动青简工具箱.cmd`，首次按提示选择解释器与共享位置。也可执行：

```bat
python 程序文件\main.py
```

启动代码在导入 Qt 前自检，支持 64 位 Python 3.10–3.14，具体库兼容性以运行检查为准。未满足的依赖会按 requirements.txt 补入所选解释器，首次准备缺项需要联网。不要只复制 main.py，也不要删除小型 bootstrap_wheels。

环境只读检查：

```bat
启动青简工具箱.cmd --check-only
```

切换部署位置使用 `--choose-environment`；需要同步控制台排错使用 `--no-ui`。已完成准备的环境可用 `--offline --check-only` 检查离线复用。

## 修改与检查

源代码位于 `程序文件/qingjian`。环境启动逻辑与业务代码分开，约束见 `程序文件/AGENTS.md` 和 `程序文件/测试说明.txt`。按修改范围运行相应测试；界面与转换更新还应检查真实窗口与业务输出。

```bat
cd 程序文件
python -m pip install pytest
python -m pytest tests -q
```

仓库中的固定来源、大小和 SHA256 用于验证下载，不应无依据更改。requirements-lock.txt 保留已验证构建环境快照；源码自检依据 requirements.txt 的兼容范围，不能把构建工具误当运行时缺项全部补入。

## 生成下载包

在 `程序文件` 内运行 `python package_source.py --help` 或 `python build_cmd.py --help` 查看当前参数。轻量包使用 `--entry-mode cmd`；完整包通过 build_cmd.py 收集可移动解释器、依赖与已验证的本地引擎。旧 EXE 构建源码仅作历史保留，不作为本次发布入口。

完整包构建复用指定的本地资源：从所选 Python 环境收集符合要求的库，从已验证的本地目录复制 LibreOffice 及其他转换组件。打包过程本身不下载或安装组件；缺少必要资源时应先补齐并验证，再重新构建。复制、校验、压缩所需时间不代表正在重复下载。

完整包的组件版本与许可清单应由本次实际分发的环境生成，不能用旧构建机的完整 `pip freeze` 冒充。分发的来源、构建和校验记录不得携带构建机绝对路径、个人账号或用户配置。

用户下载包保持“启动CMD＋使用说明＋程序文件”三项根目录，不能因打包目录名称多包一层。GitHub 仓库额外带 README、许可和开发资料。大型运行时、实际个人配置和构建缓存不得提交 Git；完整包和源码 ZIP 放在 Releases 附件。仓库保持私有，下载者须有仓库访问权限。

本仓库通过 `.gitattributes` 保留文件原始字节，避免 CMD 及历史构建源码的行尾被 Git 自动改写，导致固定哈希检查失效。

## v0.11.2 发布检查

本版将当前界面、公文中性预设、返回导航、12 项组合流程、交互检索与查重、透明度及吸附、记事双窗修复同步到完整运行包和轻量源码包。两包使用同一版业务源码，不复用旧版程序本体；完整包可复用经校验且符合要求的本地运行资源。

正式发布应集中检查启动、业务回归及实际窗口交互，并核验：

- 完整包在不借用系统 Python、Java、7-Zip、Ghostscript 或 LibreOffice 时使用包内环境，本地业务可离线运行。
- 源码保留首次位置选择、共享解释器补缺、国内来源回退及已初始化环境的离线复用；启动实现未改时结合既有安装验证、启动契约及文件一致性检查，不反复下载大型组件。
- 公文默认值和示例无特定雇主身份，返回保留原页面状态；组合流程按真实文件验证输出串联、类型匹配、取消与原件保护，窄窗可访问全部参数。
- 两种 ZIP 的成员路径、CRC、三项根目录、版本、组件清单、许可材料及源码一致性正确，源码包未混入运行环境或个人数据。
- 完整包、源码包及发布页的 SHA256 相符；旧版发布保留，不覆盖历史附件。

具体结果以本次验收记录与发布说明为准。测试不能代表每台办公电脑的终端防护策略均已允许，现场限制须根据实际运行结果处理。

## 发布验收

73 个测试文件采用隔离进程集中回归，最终 1433 项通过、6 项因缺少固定公共 MSG 样例跳过，无未解决失败。使用完整包自己的 Python、库和转换引擎，在仅保留 Windows 系统 PATH、禁用用户 site 和在线补缺的子进程中完成两次 CMD 检查及 57 项实际离线业务/格式转换；原生页面返回、清洗滚动布局、记事双窗和普通 CMD 独立启动也通过。
