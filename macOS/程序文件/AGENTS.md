# 青简工具箱后续版本必须保留的要求

## Mac 适配补充（0.12.0 起）

- Mac 发行根目录保留三项：`启动青简工具箱.command`、`使用说明.txt`、`程序文件`。Windows CMD 交付原则在 Windows 包继续适用，Mac 不携带 Windows Python/EXE/DLL 充当可运行组件。
- Mac 源码在 Qt 导入前走 `bootstrap_macos.py`，无 Python 入口为 `launcher/start_macos.command`；保留 `macos-runtime-sources.json`、`startup_macos_native.py`、`macos-native-sources.json`、共享解释器安装与国内镜像。首次确认部署位置前不下载/建立环境。位置记忆放包外，替换源码后复用并校验。
- 不绕过 PEP 668：已完善的受管理 Python 可复用；缺包时提示选择兼容可写解释器或独立部署，不加 `--break-system-packages`，不修改 Homebrew、系统 Python 或系统安全设置。
- Mac 完整运行包只在真正的 macOS 构建，按 arm64 / x86_64 分别验证 Mach-O、可移动 Python、全部原生引擎以及断网启动；打包成功与 Windows 模拟测试不能替代 Mac 验收。完整包本地缺件明确报错，不静默联网安装。
- 当前支持系统下限 macOS 14.4。未完成签名/公证和实机交互测试如实说明，不关闭 Gatekeeper、不移除 quarantine，不伪装签名；只提供系统正常打开方式。
- GitHub 云端构建使用已授权的标准 macOS runner，手动触发并限制超时；保持用户最近确认的仓库可见性（本轮已确认保持当前公开），不擅自改可见性或计费设置。失败后排查具体原因，不无限重复消耗额度。

## 原有功能及交付约定

仅适用于本项目的开发、更新与打包；用户的具体任务优先。

- 自2026-11-02起，后续版本固定交付两种包：`完整运行包`＋`轻量源码包`。完整运行包内置全部必要运行环境和离线转换组件，在没有系统 Python、Java、LibreOffice、7zip、Ghostscript 的电脑上也能运行。轻量源码包保留程序源码、启动器、必要说明、许可、启动准备代码及固定版本下载/校验清单，不捆绑大型运行时、第三方转换引擎、上游源码压缩归档或下载/构建缓存；不再要求用户另行取得第三种离线组件包。
- 轻量源码启动必须自动检测并补齐所选功能需要的全部环境，包括 Python、Python 依赖、LibreOffice、OFD 所需 Java 与桥依赖、Ghostscript、7zip 等原生组件。复用已就绪且兼容的环境，只下载缺少或不兼容的组件；无 Python 时也须从根启动器完成准备。首次补齐缺项需要联网，完成初始化后可离线运行，不依赖本地 GPU 或模型。
- 轻量化必须同时实现组件的自动补齐与运行路径发现，不能只从源码 ZIP 删除引擎文件。原生组件下载同样使用已核验的官方源和备用路径、HTTPS、固定大小与 SHA256；优先国内镜像，缺少合适静态镜像的组件可用实测可达的下载加速备用，并准确标注来源类型；组件部署、缓存、临时文件和日志跟随用户选定位置，不强制放在 C 盘，不修改系统 PATH 或执行系统级安装。源码保留必要的许可、来源与适用源码获取说明；分发组件时一并处理对应许可材料。
- 后续发布前须在没有预置原生引擎的轻量源码解压目录验证：首次启动补齐全部缺项、各类转换实际可用、再次启动离线复用、已有兼容组件不重复下载、主源失败时国内备用成功、所有来源失败时明确提示且可重试。记录两种包的体积及内容清单，检查轻量源码未混入大型组件；完整包仍执行无外部环境的离线验证。现有已发布版本保持不变，以上原则从下一次打包实施。
- 源码的 `main.py` 必须在导入 Qt 等第三方模块之前完成环境自检。现有环境完整时直接复用，不联网、不重复安装。
- 源码依赖采用共享解释器策略：选择本机可用的 Python，缺少或版本不兼容的包通过标准 pip 直接补入该解释器环境，已满足要求的包复用；不因每个项目重新创建私有 venv。安装目录无写权限且 Python 支持用户 site 时采用标准用户安装；显式指定的 venv 仅在该 venv 内安装，共享范围不跨不同解释器或不同 venv。
- 不修改全局 pip 配置、PATH 或系统安全策略。无可用 Python 时保留源码启动器及可重建的启动器源码，下载并解压备用 Python，不进行系统安装、不改 PATH；其依赖同样安装到所选解释器环境。
- 每轮更新交付的源码均须包含 `bootstrap.py`、`startup_engine.py`、`startup_native.py`、`startup_shared.py`、`runtime-sources.json`、`native-sources.json`、`启动青简工具箱.exe`、`launcher/SourceLauncher.cs` 和本文件；CMD交付模式保留准备脚本及上述C#历史重建源码，但按用户要求不分发这些自编译EXE。
- 源码ZIP通过 `python package_source.py` 生成，便携版通过 `build.py` 构建；两个入口均须保留启动文件、导入顺序、`DEPENDENCY_INSTALL_POLICY = "shared-interpreter"` 及启动器构建哈希检查，不覆盖已发布版本。
- Python、pip、文档排版引擎保留官方源及已经核验的国内镜像备用；其他原生组件保留官方源及已核验的国内镜像或下载加速备用；使用 HTTPS，下载后校验固定 SHA256 与大小，不执行未验证的文件。
- Python 包源按单源顺序尝试失败回退，不使用 `trusted-host` 或关闭证书验证，不同时混入多个 `extra-index-url`。
- 源码必须保留 `bootstrap-wheels.json`、其中列出的 `bootstrap_wheels` 小型纯Python轮子及可复现重建脚本。只提供源码发行包的间接依赖不能被 `--only-binary=:all:` 无提示排除；通过逐文件大小/SHA256校验后提供精确wheel URI，不扫描任意候选目录、不放开所有源码构建。发行前必须在不复用系统site-packages的空环境实际安装全部直接及间接依赖并运行pip check；不能用已有完整开发环境的导入检查代替首次安装验证。依赖解析失败须准确提示原因，最后一个镜像失败不得继续宣称切换备用。
- 文档转换引擎优先复用现成组件；缺失时只解压到专用目录，不执行系统安装或要求管理员权限。
- 已完成初始化后应可离线启动；便携版 EXE 始终跳过源码在线准备逻辑。
- 记事提醒与脱敏记忆库保存在用户数据目录；升级保留现有文件，不将真实用户事项或规则加入源码/便携ZIP。提醒模块不能随主窗口销毁，完全退出模块后不得继续弹出提醒。
- 事项预约日期和小时分钟须有清晰可见的独立输入，时间采用24小时制HH:mm，支持键入和箭头调节；按分钟用于预约、定期及提前提醒。兼容旧事项时间、循环设置和存储格式。
- 新增或调整依赖时同步维护 requirements.txt、依赖导入/版本自检规则与启动测试。调整下载组件版本时重新核验官方校验值及至少一个国内镜像或下载加速备用地址，禁止推测链接。
- 办公扩展工具保持中文步骤、虚构示例、来源定位与结果清单，处理副本不覆盖原件。未经后续用户明确要求，不加入OCR、录音转写或其他需要本地模型的功能。
- 快速转换统一保留在独立转换浮窗，首页不再显示原六个快捷方式。转换保持明确目标、拖入或粘贴后自动后台执行；本地输入逐个输出到各自原目录，纯链接输出到用户选定位置。所有拖拽只接受复制语义，原件与已有结果绝不覆盖；失败、取消和只读目录必须明确反馈。完整工具页继续用于需自定义参数的操作。
- 交付前至少验证：完整环境不触网、仅补缺失或不兼容依赖、标准用户 site 可见、显式 venv 的安装范围、主源失败备用源成功、所有源失败可理解提示、已初始化离线复用、无 Python 入口、冻结版跳过网络准备，以及原有功能的相关回归。以后每轮更新均须保留共享解释器安装、自检及国内镜像回退能力。

- 默认主窗口保持屏幕三分之一宽以内的贴边布局（含原生边框），最大化可展开，恢复时按当前屏幕重算；转换浮窗与记事提醒保持明显入口，完整工具和说明均可访问。复杂设置滚动不得遮挡底部控件。
- 首页固定上下两个功能区：上方为各分组工具入口，下方为自定义区；图片、文字、待办事项必须三选一，通过按钮切换并记住选择，不同时挤在页面中。图片和文字占用完整展示面板并显眼呈现。图片与文字分别支持顺序循环、随机循环、单个不循环，允许选择固定内容与间隔；旧素材路径和播放偏好升级保留。事项复用记事本数据且只读展示，不能消费提醒。用户素材只读、处理有界；隐藏首页或切换模式后停止未显示内容的轮播，避免频繁扫描文件夹和在主线程解码超大图。截图、测试与发行包不包含真实用户素材或设置。
- 转换圆环须在文件拖入且鼠标尚未释放时支持滚轮翻页，向下下一页、向上上一页；松开时按当前页和指针位置选择目标，翻页不触发处理。Windows OLE拖拽的事件桥只在有效悬停期工作，退出悬停、取消、隐藏、禁用和退出程序后释放；同时保留正常滚轮、按钮分页与复制语义。发布须验证真实Windows拖拽，不仅发送合成QWheelEvent。
- 完整包使用launcher/PortableLauncher.cs的精简启动器，源码包继续保留完整环境准备启动器；两者均以当前用户权限运行。重建脚本和构建哈希一并维护。系统在启动器运行前的拦截不能声称由内部代码已修好，保留只读启动诊断入口，禁止自动调整权限、安全软件或系统兼容性策略。

- 轻量源码包和完整运行包解压后，根目录恰为启动器、`使用说明.txt`、`程序文件` 三项；自0.10.2起用户指定发布的启动器为`启动青简工具箱.cmd`。随包配置、引擎、许可和其余文件均放入程序文件；源码另行部署的备用运行时、原生引擎及缓存、日志存放在用户选定的部署位置；复用已有 Python 时依赖继续补入该解释器的标准位置，不得向发行根目录新增运行日志或配置。
- 源码首次交互启动必须在下载或建立运行环境之前，让用户选择复用现有 Python 或自选部署位置；记住选择。复用模式明确说明另选目录只用于转换引擎、缓存、临时文件和日志，默认建议包外同盘的“青简共享环境”，回车采用或自选其他绝对路径，确认前不创建运行目录；不得将其表述为重新部署Python。成功准备后跨版本记住包外位置；当前配置、明确参数及重新选择优先。旧版默认包内runtime应复制校验到共享目录后再使用，保留原件；迁移成功后删除旧源码不应导致重下组件。已独立部署在外部的有效组件直接复用；已删除或损坏的文件须如实补齐，不能凭索引跳过校验。索引仅存小型位置元数据，组件与缓存仍留在选定盘；完整包直接使用包内组件。
- 独立转换浮窗可移动、折叠并关闭；主窗口关闭后已启动的后台任务可以完成。与完整工具共用一个执行槽，不能并发使用 PDFium。拖拽悬停只识别扩展名，实际转换放在后台。
- 本轮新增转换限已选类别 01—15、20，以及无需 GPU/模型的轻量 EPUB。不得顺带加入音视频、CAD、OCR、本地模型或 calibre。未支持的方向不显示为可用目标；转换的内容损失与格式限制必须有中文提示。
- 发布前核验两种包的三项结构、源码首次位置选择、当前全部直接依赖的自检（0.9.0为19项）、全部原生组件的自动补齐、完整包无系统 Python/Java/7zip/Ghostscript 时使用包内引擎，并对新增格式进行真实文件往返验证。随完整包分发的原生组件附版本、来源、校验值、许可及适用的源码材料；轻量源码不携带大型上游源码归档。不把构建缓存、用户部署选择或真实办公数据加入发行包。

- 自0.10.2起按用户要求交付CMD完整包＋CMD轻量源码包。CMD直接调用Python执行源码，不转调自打包工具箱EXE；完整包内置可移动Python及全部离线组件，源码包保留无Python时自动下载和首次位置选择。旧EXE构建文件可作为历史重建来源保留，CMD发行包不带这些自编译EXE。包内Python及原生引擎仍包含上游EXE/DLL，不声称无可执行文件或可以绕过公司安全策略。禁止修改执行策略、防护、权限、注册表或伪装签名；办公机是否可用以现场验证为准。
- 轻量源码普通CMD启动在自检/补缺后独立运行界面并退出准备控制台；关闭准备控制台不得连带关闭已启动的主界面、记事或转换小窗。优先所选解释器同目录pythonw，无pythonw时使用同一解释器无控制台窗口启动，GUI就绪标记匹配实际解释器，输出写选定运行目录的日志；不得靠更换其他Python或改系统策略实现。保留--no-ui同步诊断及检查/仅准备模式。

- 0.11.0本轮仅交付轻量源码包；等用户明确要求后再更新完整运行包并同步GitHub，不能在中途自动发布。保留此前两个发布ZIP，不下载或复制无关大型运行时到源码工作区。
- 全局外观提供50%—100%整窗不透明度及吸附开关，在原用户数据目录原子保存；主窗、记事双窗、转换与后续结果窗口实时一致。记事原有玻璃面板设置继续有效。吸附只处理本应用窗口的主动拖动，支持屏幕边缘、小窗互相对齐及Alt临时绕过，不修改系统窗口设置，不增加全局鼠标钩子或轮询。
- 主界面全文检索与重复文件查找使用独立交互结果窗口，不再经过导出任务，不创建结果目录、检索报告或正文历史。检索左侧显示文件名和地址，单击右侧展示关键词命中原文和位置，支持高亮、切换、停止及有界预览；关闭正文清理后可以再次检索。旧后端导出接口保留兼容。
- 查重默认不勾选，批量处理仅支持移到整理目录或系统回收站，处理前列出完整路径及每组保留副本，每组至少留一份；重新核对内容及文件身份，不覆盖现有文件，不以永久删除作为回收站失败降级。异常、取消和已完成项须明确显示。扫描、检索、整理与转换共享执行槽，只在线程真正结束后解锁，不在GUI线程扫描文件；应用退出须取消并等待工作线程。
