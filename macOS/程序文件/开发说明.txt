本版发布原则
固定交付“完整运行包＋轻量源码包”。完整运行包内置全部必要环境和离线组件；轻量源码保留启动器、代码、许可、固定下载清单和小型OFD桥，排除大型运行时、转换引擎与上游源码归档，不要求另取组件包。
startup_native.py在用户所选runtime目录下补齐7zip、Ghostscript、Java JRE及OFD库；原Python、pip和LibreOffice准备保持。下载采用固定大小/SHA256校验，原生引擎部署后逐文件验证，再通过QINGJIAN_NATIVE_COMPONENTS传递准确组件目录。完整包忽略外部原生组件映射，始终使用包内组件。
已有完整兼容环境不联网，缺项首次联网补齐后可离线使用。官方来源、国内镜像或已实测下载加速备用、共享Python依赖、首次部署位置选择、两种包根目录仅三项均保留。Java/Ghostscript备用属于GitHub下载加速，按实际标注，不称为大陆静态镜像。已发布版本不覆盖。

本版源码共享Python依赖
用户已明确选择将依赖补入本地Python环境。源码启动使用选中的Python，按requirements.txt检查版本和实际导入，仅为缺少或不兼容的模块调用标准pip；已满足要求的模块不重复安装，不再创建每项目私有venv。
本机Python优先；python main.py使用当前解释器，启动器的--python参数可显式指定解释器。系统安装目录不可写且用户site可用时使用标准--user安装；显式venv仍限制在其自身环境内，不向它不可见的用户site安装。模块仅在相同解释器及其有效site中共享，多个程序的依赖版本须兼容。
pip缓存和准备临时目录跟随所选运行目录，可复用下载；安装不使用每项目--target目录，不修改全局pip配置、PATH或系统策略。PIP_CONFIG_FILE=系统空设备仅约束本次子进程来源；官方与国内镜像逐源回退、HTTPS验证及固定独立组件哈希检查继续保留。
无Python时启动器仍在QINGJIAN_RUNTIME_HOME下下载解包备用Python，不安装到系统也不改PATH；只要后续程序显式使用这一解释器，其已安装模块同样可复用。排版引擎仍优先复用现成引擎，缺失时在专用运行目录私有解包，与Python包共享策略分别处理。
本版同时交付完整便携程序和源码，保留旧版发布文件。以后每轮源码更新均保留这一共享解释器策略、启动前自检、自动补齐及国内镜像回退，见AGENTS.md；build.verify_source_startup检查DEPENDENCY_INSTALL_POLICY标记及原有导入顺序、启动器构建SHA256。

独立记事与提醒
notebook_ui.py用NotebookWindow协调日历与事项两个独立顶层窗口；默认拆分，通过合并/拆分操作复用同一calendar/task_list对象，保持选中日期、查询及完成筛选。owned_windows及show_windows/hide_windows/minimize_windows/close_windows供runtime统一管理生命周期。
事项行用delegate绘制可见内容，不为每个事项创建一组嵌套widgets；行内动作通过命中区域和键盘执行，标题/正文按普通文字处理。日历预先计算农历、节气和事项标记，paintCell只查表绘制；重复refresh在无数据变化时跳过重建。
calendar_index.py复用reminder_schedule规则，按日期跳跃并合并同规则等级计算可见日格标记，分钟级提醒不枚举整月每一分钟；与task_occurs_on语义逐日对照验证。
notebook_store.py保留schema1与事务原子写入；新增layout_mode/calendar_geometry/tasks_geometry，旧geometry继续存合并窗口位置。旧文件读取补默认，不因升级读取而改写原文件。
store.revision在成功load/commit后更新；运行时按revision及日期刷新UI。成功事务后重建任务索引和最近提醒阈值，未到期tick不再深拷贝全部事项，只有pending对应事项进入提醒输出。
notebook_runtime.py属于QApplication，独立管理两浮窗、1秒提醒检查、托盘、单实例和提醒卡片。重复show/tick不反复刷新列表与提醒卡样式，跨午夜按日期刷新；完全退出后释放两个窗口和本地锁。
glass.py按HWND缓存系统背景效果；透明度和几何设置不会重复调用原生接口。Windows10拖动期间暂时停用昂贵模糊并在结束后恢复；不支持系统玻璃时保留可读半透明面板，正文不随背景透明。
notebook_calendar.py包装随源码提供的MIT lunar_python 1.4.8，仅展示公历、农历、节气及节日，不推算法定调休。来源与固定SHA256见lunar_python/来源.json，无新增运行依赖。
独立启动：python main.py --notebook；冻结程序同参数。--notebook --screenshot 路径将当前模式两个组件抓取后并排合成，不截取其他程序。截图默认使用专用/内存数据，禁用真实通知、声音、托盘及单实例锁。

本版脱敏规则与记忆库
redaction_editor.py提供可增删、排序和批量粘贴的两列规则表；set_content/option_rules兼容旧custom_sensitive与custom_sensitive_rules。正式传参保持结构化，不通过等号/换行文本序列化，保留字面等号、换行和首尾空格。
redaction_memory.py使用标准库原子保存命名规则组；读写深拷贝，每组5000条、200组、10MB。写入成功后才变更内存；失败回滚，坏文件保留并拒绝覆盖，错误不包含规则正文。
redaction_library.py提供本地搜索、只读预览、追加/覆盖、更新、重命名、删除及自动载入设置。载入失败保持对话框打开。app.py仅在下次启动时向redact场景预置默认规则，其他场景和参数不受影响。
规则记忆文件与profile.json同目录，名为redaction-library.json。Window(data_path=None)与截图默认只用内存，生产由QINGJIAN_USER_DATA或Qt用户数据目录注入；不在源码或程序旁保存用户规则。
自定义规则沿用原有从上到下依次替换的执行方式；新增功能没有额外运行依赖，源码启动自检与国内备用源保持不变。

源码启动自检为后续每轮更新的固定要求，见项目AGENTS.md。
main.py在导入第三方库前调用bootstrap.py：完整现有环境直接复用，否则交给中文源码启动器准备组件。冻结程序通过sys.frozen跳过这一路径，保持离线。
bootstrap.py仅用标准库，检查requirements.txt全部模块与版本；缺依赖时向所选解释器或其标准用户site补齐，使用固定hash的pip wheel及逐源回退安装。自检和运行必须识别相同的用户site，不能因隔离启动参数将已安装用户模块隐藏。PIP_CONFIG_FILE=系统空设备仅影响子进程，不读取或修改用户/系统pip配置；不加trusted-host或extra-index-url。
runtime-sources.json记录固定的Python/pip/LibreOffice版本、SHA256、大小、官方来源及国内备用。每次改版本必须重新核验来源，不能假设镜像永久可用。
launcher/SourceLauncher.cs为不依赖Python的.NET Framework启动器，支持下载、校验、安全解包、进度和取消。重建：python launcher/build_launcher.py；生成的build-info.json绑定启动器与C#源码SHA256。
build.py的verify_source_startup发布检查在缺少启动文件、共享解释器策略标记缺失、入口未先自检或启动器与源码哈希不一致时拒绝构建。
源码发布统一运行 python package_source.py；同样强制自检文件检查，逐成员核对ZIP与源码SHA256，排除缓存、部署选择、虚拟环境、LibreOffice及support大型运行组件/上游源码归档（保留小型桥、许可、来源与源码说明），不覆盖已有版本。--output可指定源码目录以外的ZIP路径。
startup_engine.py只读MSI数据库及CAB数据，在私有目录还原引擎并带上AMD64运行库；不执行MSI安装，排除ARM64运行库同名覆盖。
自检准备协议为UTF-8 JSONL，event为log/progress/error/ready；ready携带实际python和启动环境变量。启动器用JobObject管理本次准备及pip子进程，取消不影响无关Python；主GUI单独启动。
第一次交互启动在任何下载前选择复用已有Python或指定共享部署目录，支持D/E盘；配置保存在程序文件/config/startup-selection.json。备用Python、排版引擎、下载、缓存、临时目录及准备日志都跟随所选运行目录，支持QINGJIAN_RUNTIME_HOME；运行依赖仍安装在所选Python标准位置。初始化后断网可重复使用。新增依赖须同步bootstrap.MODULES及相关测试。

日常运行可在Windows 64位、Python 3.12或兼容环境的源码目录执行python main.py，依赖将按上述规则自检并补齐。以下venv仅用于开发和可复现构建，是开发者明确创建的隔离环境，不是程序运行时自动创建：
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-build.txt
.venv\Scripts\python main.py
.venv\Scripts\python -m pytest tests -q
requirements-lock.txt记录本次构建实际版本；可用于复现。

从LibreOffice官网下载Windows64发行包并核验官方SHA256，用msiexec /a行政解压，不需要安装到系统。
.venv\Scripts\python build.py --engine "D:\build\LibreOffice" --output dist --work build
参数指向含program/soffice.exe的引擎目录。完整分发dist\青简工具箱，不能只分发exe。
PyInstaller随包携带Python、Qt、模块；引擎位于程序文件/engines和程序文件/support，开发机才需联网准备依赖。
构建脚本限制依赖扫描PATH，避免其他软件ICU DLL混入Qt；将引擎System64运行库复制到program供应用本地加载。

冻结程序检查：
启动青简工具箱.exe --no-ui -- --self-check "D:\QA\自检.json"
启动青简工具箱.exe --no-ui -- --screenshot "D:\QA\界面.png" --page 0
--page为0至16。截图默认offscreen，设置QT_QPA_PLATFORM=windows可检查实际Windows缩放。
不传--page时截图为首页；--scene official/materials/redact/compare/template/convert指定场景；--surface home/catalog/presets/history指定页面。
QINGJIAN_USER_DATA为本地配置目录覆盖，生产默认Qt AppLocalDataLocation；截图未指定覆盖时仅用内存，不污染真实历史。
--self-check现有57项，包含记事提醒持久化、循环与稍后提醒、离线农历节气、200条脱敏规则的记忆与实际替换，以及随包PPT模板实际填充；完整包需保留示例材料。构建后独立core自检前也要复制该小目录，不需要复制第二套引擎。
自检在报告目录下建立临时样本，完成后清理；不接触用户材料。无console的exe可用Start-Process -WindowStyle Hidden -Wait等待自检退出。

接口：run_*(tool,sources,folder,options,progress,cancel)；progress(done,total,message)，cancel()返回是否停止。
返回outputs包含产物和报告，data_outputs仅业务产物，errors与warnings分别表示失败与需复核项。
文件归档必须先plan_organize，再把返回值通过options['_plan']执行，执行前重新核验源和目标；组合流程只允许copy。
导出配置递归剔除密码和私有_plan，不包含可执行Python/Jinja代码。

边界：无OCR，无语义脱敏；公式需要缓存；原地改名只处理文件，不递归移动文件夹。应用为单用户本地桌面程序，无对外HTTP服务或业务程序自动更新；源码仅在环境缺失时联网准备组件。
